# Implementation decisions

Baseline: 2026-10-22 (Asia/Colombo), clean `develop` at `8c7bf54`. Feature branch: `feature/boutique-redesign-security`. No production deployment, remote secret changes, payments or customer-data changes are authorized by this work.

1. Preserve React 19 / Vite, ASP.NET Core 8 Identity, EF Core and SQL Server, existing migrations, permission vocabulary, transaction boundaries and provider-qualified historical amounts. Two later additive migrations retain cart variant selections and scoped customer requests; historical migrations are unchanged and the new rollback paths protect existing choices/records.
2. The supplied Markdown is the execution specification. The 18-page PDF is supporting context; its weaker password rule, demo-inventory suggestion, automatic host migration and one-phase-per-session advice are superseded by the Markdown. Seven original screenshots were not separately attached; reproduce against disposable local fixtures and label those images accordingly.
3. Prioritize server authorization and a separate staff artifact. Customer routes must have no imports of staff modules. Staff APIs must fail closed until explicitly enabled and authenticated with a recent verified second factor. A public static staff artifact cannot itself make downloaded JavaScript confidential: deployment must also enforce an identity-aware gateway if that is a business requirement.
4. Keep in-memory access tokens and the existing rotating HttpOnly refresh-cookie architecture. Add revocation binding and explicit cross-origin protections rather than replacing authentication wholesale. Refresh preserves MFA only with a protected, user/stamp/family-bound grant at its original verification time; it never extends the assurance window.
5. Updated by the subsequent user request: new/reset/changed passwords use 6–128 Unicode code points, including an uppercase letter, a number and a punctuation/symbol character. Existing hashes and sign-in remain compatible. Keep the local blocklist boundary; do not claim comprehensive breach-corpus coverage.
6. Select warm editorial commerce: ivory, navy, restrained blue and warm accent, a split hero and labeled original vector material studies until genuine photography is approved. Do not generate imitation customer photographs, fake inventory, reviews, contacts or delivery claims.
7. Preserve CMS hero contracts and browsing/checkout/proof workflows. Replace incorrect shape rendering and expose only configured production options. Backend quotes remain authoritative.
8. Host/domain, live catalogue, payment-provider selection/currency, email delivery, policies, actual staff provisioning/recovery operations and production restore evidence are release gates. Local MFA enrollment/recovery is implemented and tested. Local fixtures are disposable test data, never business content.

Baseline verification: backend 241 passed / 11 skipped / 0 failed; frontend 111 passed / 0 failed. SQL skips are not evidence of database correctness. Further observed results are recorded in TEST_AND_RELEASE_REPORT.md.

9. Circular shapes keep equal dimensions in the editor and are validated server-side. A legacy unequal circular configuration must be corrected before it can receive a new quote. Private resource endpoints now use the same staff policy as operational controllers instead of a role-only override.

Operational flags remain disabled until approved.
