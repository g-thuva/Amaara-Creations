# Personas and journeys

These are task-based design assumptions, not invented user-research findings.

| Buyer | Main task | Friction to remove | Successful journey |
| --- | --- | --- | --- |
| Everyday personalization buyer | A name/phrase decal for an object or vehicle | Shape confusion, unclear dimensions and duplicate prices | Open designer → configured shape/size → preview text → server quote → save → checkout |
| Small business owner | Repeated labels in a known size/quantity | Hidden tier rules, artwork handling and losing a saved design | Browse or design → private artwork → review options/quantity → persisted order → proof when required |
| Event organizer | Coordinated personalized details | Unverified materials/timing and unclear proof revision | Published collection → permitted options → saved work → review exact proof revision → order/production status |
| Returning customer | Reopen artwork or follow an order | Mixed admin/account navigation and missing preview | Sign in → Saved designs or Orders → authorized detail → edit/review/track |
| Studio operator | Review orders, proof work and fulfilment within assigned permissions | Public staff surface and missing step-up | Separate sign-in → verified TOTP → permitted module → audited mutation → sign out |

Recovery journeys: empty catalogue offers the designer; no matches offers clear filters; invalid upload preserves the design; unavailable payment never becomes paid by redirect; stale design versions preserve server conflict handling; expired staff assurance requires reauthentication.
