# Media security

Public delivery and private storage are separate concerns. Both buckets stay private, encrypted (SSE-S3/AES256), with ACLs disabled and Block Public Access enabled. CloudFront OAC grants one distribution read access to only public `avatars/*` and `products/*`; see [AWS OAC guidance](https://docs.aws.amazon.com/AmazonCloudFront/latest/DeveloperGuide/private-content-restricting-access-to-s3.html). The private bucket has no public/CDN allow statement.

The [application IAM template](../../deploy/storage/application-policy.example.json) grants GetObject/PutObject/DeleteObject to four exact bucket/prefix resources. It does not grant IAM changes, bucket-policy changes, object ACL changes, object listing, version deletion or all-bucket access. `s3:*` appears only in the bucket-policy **Deny insecure transport** statements, never an application Allow. Use separate dev/prod identities; a tightly scoped permissions boundary is useful when the execution role has other policies. Audit all effective permissions, including resource policies and SCPs.

No AWS access keys are read from application JSON or sent to React. Official SDK v4 default credentials support named profiles, temporary session credentials and execution roles. SSO helper packages are included; `AWSSDK.Extensions.NETCore.Setup` is unnecessary because existing DI directly manages one `IAmazonS3` client. Retry mode is Standard with three retries and a bounded request timeout; caller cancellation propagates. Do not log signed grants, credential values or confidential SDK request bodies.

Public object keys use GUIDs without user IDs/email/original filenames. Private keys have a purpose/design/date/GUID structure, but **the path is never an authorization claim**. Database design/asset associations plus existing owner or `ManageOrders` policy checks resolve reads. Staff policy enforcement includes the existing management/MFA assurance checks. Customer attempts to access another customer's bytes are hidden as 404; anonymous private access is 401 and unauthorized proof uploads are forbidden. The public endpoint validates a strict public-key grammar and cannot select a bucket or private prefix.

All uploads and CLI imports retain bounded input reads, MIME/signature checks, dimension checks, full Skia decoding, orientation normalization, metadata removal and configured scanning before persistence. GIF remains avatar-only. Output is lossless PNG without rescaling. Existing APIs do not accept SVG/PDF/active print documents or retain a second original; expanding format support or high-resolution ceilings needs a separate quarantine/preview design. A required unavailable/rejecting scanner fails closed before S3 receives anything.

Public images use immutable random keys, `image/png`, immutable cache control and `nosniff`; the proxy/CDN does not serve arbitrary object MIME types. Private responses are authorized per request, `private, no-store`, `nosniff`, sandbox CSP and safe attachment dispositions. Private response streams own/dispose their S3 response and support cancellation without buffering the whole download. Ranges are unavailable on non-seekable S3 streams; local seekable downloads retain existing behavior. Private URLs are application URLs, never stored presigned URLs.

The current implementation selects SSE-S3 explicitly. If a documented need for SSE-KMS arises, change the upload encryption/key setting and review KMS key policies before enabling it. The execution role would require `kms:GenerateDataKey` for writes and `kms:Decrypt` for reads, scoped to the selected key with S3 service/encryption-context conditions. CloudFront OAC also needs a constrained key-policy grant. Do not simply change bucket defaults while the application explicitly requests AES256 and claim KMS is active.

Cleanup reserves objects before upload and stores delete work atomically with media reference removal. It waits seven days for unclaimed uploads (configurable 24–2160h), then rechecks committed media/user/product/order snapshot and embedded CMS references. Origin-qualified older avatar URLs are protected too. Failures retain the work item with backoff. Monitor backlog/oldest age; do not expire current S3 objects using a broad lifecycle rule. This is eventual recovery, not an S3/SQL distributed transaction. Keep uploads/profile updates paused during migration/rollback and recovery sweeps; very long abandoned editing sessions must re-upload after the grace period.

Immutable CDN keys prevent stale replacements. A public image already cached or downloaded cannot be instantly revoked by deleting S3 bytes; approved emergency removals may require CloudFront invalidation and caches can still exist outside your control. Private artwork has no such public cache path.

Cloud infrastructure controls cannot be established by mocked application tests. The owner must verify bucket policies, anonymous denial, role isolation, OAC and account-level public-access controls against approved test resources before production.
